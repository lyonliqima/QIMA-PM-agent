QIMA PM Agent v1.0.2

How to Use the Six Skills

This guide explains the six user-facing skills in QIMA PM Agent: when to use each skill, how to ask, what the workflow does, and what output to expect.

Install or Update

Install from the GitHub marketplace, then use the slash commands inside Claude Code.

/plugin marketplace add lyonliqima/QIMA-PM-agent
/plugin marketplace update qima-pm-agent
/plugin install qima-pm-skills@qima-pm-agent

Skill Map

The skills cover the PM workflow from discovery to handoff: understand the codebase, draft the PRD, critique the PRD, critique the design, improve UI quality, and create Jira implementation tickets.

PRDwrite-prd

Drafts a Confluence-ready PRD from scattered context.

Codebasecodebase-understanding

Maps repos, services, APIs, teams, and documents.

Reviewprd-critique

Reviews PRD quality against QIMA PMO/CPO gates.

UIui

Shapes, builds, critiques, audits, and polishes UI work.

Designdesign-critique

Connects Figma, PRD, code, and Jira evidence.

Jiraticket-breakdown

Creates an Epic and implementation tickets after approval.

The Six Skills

Each skill can be invoked with its slash command or by asking naturally when the intent is clear.

PRD Drafting

write-prd

Use this when you need to create a complete PRD from an idea, source materials, Figma designs, meetings, or Confluence context.

/write-prd Supplier Confirmation
Workflow
  1. Gather context.
  2. Run depth questions.
  3. Create outline and draft.
  4. Run PRD critique loop.
  5. Write to Confluence.
Outputs
  • Confluence PRD draft
  • Source ledger
  • Open questions
  • Review-loop fixes

Technical Discovery

codebase-understanding

Use this when you need a PM-readable map of where a feature lives across repos, services, APIs, documents, and owning teams.

/codebase-understanding Interactive Report
Workflow
  1. Expand feature keywords.
  2. Search docs, Jira, repos, and service catalogs.
  3. Synthesize a structured brief.
  4. Mark unknowns as not found.
Outputs
  • Markdown brief
  • Repo / service / API / team table
  • Related links
  • Top gaps

PRD Review

prd-critique

Use this to review an existing PRD for readiness, QIMA template conformance, voice/register quality, hallucinated details, and best-PRD pattern coverage.

/prd-critique <prd-file-or-confluence-url>
Workflow
  1. Read the entire PRD.
  2. Check QIMA hard rules first.
  3. Review generic PM quality dimensions.
  4. Group findings by severity.
Outputs
  • High / Medium / Low findings
  • Missing sections
  • Voice and format checks
  • Ready-for-review verdict
/prd-critique https://qima.atlassian.net/wiki/...
Review this PRD and tell me if it is ready for PM review.
UI Work

ui

Use this as the single entry point for UI planning, building, critique, audit, polish, responsive adaptation, typography, motion, performance, and copy improvements.

/ui polish this component
Workflow
  1. Route the intent to a mode.
  2. Confirm constraints when needed.
  3. Apply the mode playbook.
  4. Edit code or return findings.
Common modes
  • shape / craft
  • critique / audit
  • polish / layout / typeset
  • adapt / harden / optimize
/ui make this page responsive on mobile
/ui harden empty and error states
Evidence-Based Design Review

design-critique

Use this when a design needs QIMA business validation, not just visual feedback. It links Figma, PRD rules, code evidence, and Jira history.

/design-critique <figma-url> <confluence-page-id> <repo-path>
Workflow
  1. Read Figma context.
  2. Match PRD, code, and Jira history.
  3. Extract evidence.
  4. Write an HTML report.
Outputs
  • HTML critique report
  • Evidence links
  • Severity-grouped findings
  • Recommendations
Run an evidence-based review for this Figma and PRD.
Check whether this design conflicts with past Jira decisions.
Jira Handoff

ticket-breakdown

Use this after the PRD is confirmed and ready for development planning. It creates a Jira Epic and child tickets only after explicit user approval.

/ticket-breakdown <prd-url> SP <design-url>
Workflow
  1. Read the PRD.
  2. Draft Epic and ticket plan.
  3. Wait for confirmation.
  4. Create Jira issues and links.
  5. Write links back to the PRD.
Outputs
  • Jira Epic
  • FE / BE / API tickets
  • Ticket links
  • Development Tickets section in PRD

Recommended Workflow

A typical feature can move through these skills from discovery to development handoff.

1. Scope the system

/codebase-understanding maps repos, services, teams, and documents.

2. Draft the PRD

/write-prd gathers context and writes the PRD.

3. Review the PRD

/prd-critique checks quality and readiness.

4. Shape the UI

/ui handles interface planning, implementation, or polish.

5. Review the design

/design-critique validates design against evidence.

6. Create tickets

/ticket-breakdown creates Jira work after approval.
